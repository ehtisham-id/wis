# Wildlife Information System — Documentation

This branch contains the official documentation and supporting documents for the **Wildlife Information System (WIS)** project.

The documentation is maintained separately from the source-code branches so that project reports, requirements, diagrams, and other reference materials remain organized and easy to access.

## 📚 Project

**Wildlife Information System (WIS)**

The Wildlife Information System is a centralized system designed to store, organize, and provide access to wildlife information through a structured database and RESTful API. The system is intended to support wildlife research, monitoring, conservation, and decision-making.

## 🔍 Project Scope

The WIS documentation covers a centralized database containing wildlife information such as animal profiles, population data, movement tracking, DNA records, health, behavior, and environmental data. It also defines a RESTful API for exchanging structured wildlife data.

The documented user roles include:

* Data Entry Operators
* Researchers
* Government Officials
* System Administrators

Each role has a different level of access to the system.

## ⚙️ Technology

According to the project documentation, the planned technology stack includes:

* **Backend:** Node.js + Express.js
* **Database:** PostgreSQL or MongoDB
* **API:** RESTful API
* **Authentication:** JWT
* **Frontend:** HTML, CSS, JavaScript, React
* **Version Control:** Git / GitHub
* **Data Formats:** JSON and CSV
* **Future Hosting:** AWS or DigitalOcean

## 🔄 Development Process

The project follows an **Agile development model**. Development is divided into short sprints, with each sprint involving planning, development, testing, and review. Feedback from each sprint can be used to improve subsequent development.

The documented sprint structure includes:

| Sprint   | Main Activity                                               |
| -------- | ----------------------------------------------------------- |
| Sprint 1 | Database design, implementation, and basic data entry       |
| Sprint 2 | API development and user authentication                     |
| Sprint 3 | Search, filtering, and export functionality                 |
| Sprint 4 | Testing, bug fixing, UI improvements, and final integration |
